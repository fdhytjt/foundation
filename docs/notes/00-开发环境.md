# 开发环境：JDK、Maven、Docker、IDEA

> 阶段：0　日期：2026-09-15

## 一句话解释

**JDK** 负责把 Java 代码编译并运行起来，**Maven** 负责下载第三方库并一键完成构建，**IDEA** 是写代码和调用这两者的工具，**Docker** 用隔离的容器运行 MySQL 这类外部服务。

## 我的理解

### 四个工具的关系

```text
你写的 .java 源码
      │ javac 编译
      ▼
 .class 字节码 ──▶ JVM 执行           ← JDK 提供（javac + JVM + 标准类库）
      ▲
      │ 调用 JDK 完成编译、测试、打包
    Maven ──▶ 从仓库下载依赖到 ~/.m2/repository
      ▲
      │ 集成 Maven 和 JDK，提供编辑、调试
    IDEA

    Docker ──▶ 运行 MySQL 等服务（和上面三个相互独立）
```

安装顺序有依赖：Maven 本身是 Java 程序，所以必须先装 JDK。

### JDK、JRE、JVM

```text
JDK（开发工具包）
 ├── javac、jar、jdb 等开发工具
 └── JRE（运行环境）
      ├── Java 标准类库（String、List、HashMap……）
      └── JVM（Java 虚拟机）：真正执行字节码的程序
```

- 同一份字节码可以在不同系统上运行，因为每个系统都有对应的 JVM，这就是「一次编写，到处运行」。
- Java 每半年发布一个版本，只有部分是 **LTS（长期支持）** 版本。17 是 LTS，也是 Spring Boot 3 的最低要求。
- OpenJDK 是开源代码，Temurin 是 Eclipse 基金会基于它编译发布的免费版本，属于「发行版」的一种。

### 环境变量、PATH 和 .zshrc

- **环境变量**是操作系统里的全局键值对，程序启动时可以读取。
- **`PATH`** 是一串用冒号分隔的目录。输入命令时，Shell **从左到右**依次在这些目录里找同名程序，找到第一个就执行。`which 命令名` 可以看到实际找到的是哪一个。
- **`JAVA_HOME`** 是一个约定俗成的变量，写着 JDK 的安装目录。Maven、IDEA 等工具通过它找 JDK。
- **`~/.zshrc`** 是 zsh 每次打开新终端时执行的配置文件。写进这里的 `export` 才能长期生效；修改后要新开终端，或者运行 `source ~/.zshrc`。
- **`export`** 让变量传递给从这个终端启动的子程序。不加 `export`，Maven 就读不到这个变量。

本机的配置：

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 17 2>/dev/null)
export MAVEN_HOME=$HOME/tools/apache-maven-3.9.16
export PATH="$MAVEN_HOME/bin:$PATH"
```

- `$(命令)` 是**命令替换**：先执行括号里的命令，再用输出结果替换这一段。这样 JDK 升级后路径变了，配置也不用改。
- `/usr/libexec/java_home -v 17` 是 macOS 自带的工具，会在 `/Library/Java/JavaVirtualMachines` 和 `~/Library/Java/JavaVirtualMachines` 里找 17 版本的 JDK。

### Maven

Maven 做两件事：

1. **依赖管理**：在 `pom.xml` 里声明需要的库，Maven 会自动下载这个库，以及它依赖的其他库（传递依赖）。
2. **构建**：`mvn test` 编译并运行测试，`mvn package` 打包。

依赖的来源和存放位置：

```text
Maven 中央仓库（国外，很慢）
      │ settings.xml 里的 <mirrorOf>central</mirrorOf> 把请求改道到 ↓
阿里云镜像（国内，内容相同）
      │ 下载
本地仓库 ~/.m2/repository     ← 按 groupId/artifactId/version 分层存放，下载一次，所有项目复用
```

### Docker

| 概念 | 类比 | 说明 |
|---|---|---|
| 镜像（Image） | 安装光盘 | 只读模板，比如「MySQL 8.0」 |
| 容器（Container） | 装好并在运行的系统 | 从镜像启动的实例，同一个镜像可以启动多个容器 |

- **容器和虚拟机的区别**：虚拟机要模拟一整台电脑，包括完整的操作系统；容器只隔离应用和它的依赖，启动只要几秒。
- **客户端 / 服务端架构**：终端里的 `docker` 命令只是客户端，负责把指令发给后台的守护进程（daemon）；真正运行容器的是守护进程，它随 Docker Desktop 一起启动。`docker version` 会分别显示 Client 和 Server 两部分。

### IDEA 里的两个 JDK 设置

| 设置 | 位置（中文界面） | 作用 |
|---|---|---|
| **项目 SDK** | 文件 → 项目结构 → 项目设置 → 项目 → SDK | 编译和运行**你的代码**用哪个 Java，必须是 17 |
| **导入程序的 JDK** | 设置 → 构建、执行、部署 → 构建工具 → Maven → 正在导入 | IDEA **读取 pom.xml** 时用哪个 Java，保持默认即可 |

IDEA 自己维护一份「已知 JDK 列表」，所有 JDK 下拉框的选项都来自这份列表。刚装好时列表是空的，要先在「项目结构 → 平台设置 → SDK」里点 ＋，选「从磁盘添加 JDK…」登记进去。

### 下载文件为什么要校验

SHA-256、SHA-512 是对文件内容计算出的「指纹」，改动任何一个字节，指纹都会完全不同。从镜像站下载后，和官方公布的指纹对比，就能确认文件完整、没被篡改：

```bash
echo "官方指纹  文件路径" | shasum -a 256 -c     # 输出 OK 表示一致
```

## 踩过的坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 装 `.pkg` 需要输入管理员密码 | `.pkg` 要写入系统目录 `/Library` | 改用 `.tar.gz`，解压到用户目录 `~/Library/Java/JavaVirtualMachines`，`java_home` 同样能找到 |
| 命令行下载很慢，甚至中断 | 终端环境变量里配置了远程 HTTP 代理，访问国内站点也绕了一圈 | 下载国内镜像时用 `curl --noproxy '*'` 直连，速度从约 12KB/s 提升到 2-3MB/s |
| Maven 不受这个代理影响 | Java 程序默认不读取 `HTTP_PROXY` 环境变量 | 无需处理，Maven 直连阿里云 |
| `docker ps` 报「连接不上 daemon」 | Docker Desktop 没有启动 | 打开 Docker Desktop，等菜单栏鲸鱼图标稳定 |
| 用 SSH 推送 GitHub 失败 | 网络屏蔽了 GitHub 的 22 和 443 端口 SSH | 改用 HTTPS，用 Personal Access Token 代替密码，存进 macOS 钥匙串 |
| 按英文名称在 IDEA 里找不到设置 | IDEA 是中文界面，Importing 翻译成了「正在导入」 | 用设置窗口左上角的搜索框搜关键词 |
| 「导入程序的 JDK」下拉框里没有 17 | IDEA 的 JDK 列表还是空的 | 先在「项目结构 → SDK」里登记 JDK |
| `git status` 里中文文件名显示成 `\346\250\241` | Git 默认把非 ASCII 字符转义显示 | 查看时加 `git -c core.quotepath=false`，或设置 `git config core.quotepath false` |

## 自测题

先自己回答，再点开看参考答案。

**1. JDK 和 JRE 有什么区别？开发时为什么必须装 JDK？**

<details>
<summary>参考答案</summary>

- JRE = JVM + Java 标准类库，只能**运行**已经编译好的 Java 程序。
- JDK = JRE + 开发工具（`javac` 编译器、`jar` 打包工具、`jdb` 调试器等）。
- 开发时要把 `.java` 源码编译成 `.class` 字节码，编译器 `javac` 只有 JDK 里才有，所以必须装 JDK。Maven 编译代码时调用的也是 JDK 里的编译器。

补充：Oracle 从 Java 11 起不再单独发布 JRE，但 Temurin 等部分发行版仍提供 JRE 版本。开发机上统一装 JDK 即可。

</details>

**2. 已经能运行 `java` 命令了，为什么还要配置 `JAVA_HOME`？**

<details>
<summary>参考答案</summary>

- macOS 的 `/usr/bin/java` 只是一个「替身」，它会去标准目录里找已安装的 JDK 再转交过去，所以不配置也能运行 `java`。之前没装 JDK 时看到的 `Unable to locate a Java Runtime`，就是这个替身报的错。
- 但 Maven、IDEA 等工具**约定读取 `JAVA_HOME`** 来确定 JDK 的位置，而不是依赖这个替身。
- 电脑上装了多个 JDK 时，`JAVA_HOME` 能**明确指定用哪一个版本**。这里写 `java_home -v 17`，就是把版本固定成 17，以后装了更新的 JDK 也不会用错。
- 验证方法：`mvn -v` 输出里的 `Java version` 和 `runtime` 路径，就是 Maven 通过 `JAVA_HOME` 找到的 JDK。

</details>

**3. 在 `.zshrc` 里写 `export PATH="$MAVEN_HOME/bin:$PATH"`，如果漏写了 `:$PATH` 会发生什么？**

<details>
<summary>参考答案</summary>

- `PATH` 会被**整个替换**成只有 `~/tools/apache-maven-3.9.16/bin` 这一个目录，原来的 `/usr/bin`、`/bin` 等系统目录全部丢失。
- 新开的终端里，除了 `mvn`，几乎所有命令都会报 `command not found`，比如 `ls`、`git`、`vim`。`cd`、`echo`、`export` 这类 Shell 内置命令还能用，因为它们不需要到 `PATH` 里查找。
- 补救方法：
  1. 在当前终端先临时恢复：`export PATH=/usr/bin:/bin:/usr/sbin:/sbin`
  2. 再修改 `~/.zshrc` 把 `:$PATH` 补上，或者用备份文件还原：`cp ~/.zshrc.bak-20260915 ~/.zshrc`
- 所以 `:$PATH` 的作用是：**在原有目录的前面追加新目录，而不是覆盖**。新目录放在前面，是为了让它优先被找到。

</details>

**4. `>` 和 `>>` 有什么区别？往 `.zshrc` 里写配置时为什么必须用 `>>`？**

<details>
<summary>参考答案</summary>

- `>` 是**覆盖写入**：先把文件清空，再写入新内容。文件不存在时会新建。
- `>>` 是**追加写入**：把新内容加到文件末尾，原有内容保留。
- `.zshrc` 里已经有其他配置（例如之前加的 `~/.local/bin` 路径，以及其他工具写入的环境变量）。如果用 `>`，这些配置会全部丢失，而且**不会有任何提示**。
- 补充：Docker Desktop 的命令路径写在另一个文件 `~/.zprofile` 里。它是 zsh 作为**登录 Shell** 启动时读取的配置，`.zshrc` 则是每个交互式终端都会读取。
- 好习惯：修改重要配置文件前先备份（`cp ~/.zshrc ~/.zshrc.bak-日期`）；只有确认文件不存在、需要新建时才用 `>`，比如这次新建 `~/.m2/settings.xml`。

</details>

**5. Maven 为什么需要配置镜像？下载过的依赖存在哪里？**

<details>
<summary>参考答案</summary>

- Maven 默认从**中央仓库**下载依赖，服务器在国外，国内访问很慢，第一次构建一个 Spring Boot 项目可能要等很久甚至失败。
- **镜像**是国内机构维护的完整副本，内容和中央仓库一致。在 `~/.m2/settings.xml` 里配置 `<mirrorOf>central</mirrorOf>`，就是告诉 Maven「所有本该去中央仓库的请求都改去阿里云」。
- 下载过的依赖缓存在**本地仓库 `~/.m2/repository`**，按 `groupId/artifactId/version` 的目录结构存放，例如 `junit/junit/4.13.2/junit-4.13.2.jar`。
- 下载一次之后，同一台电脑上所有项目都直接复用，不会重复下载。
- `settings.xml` 放在 `~/.m2/` 下是**用户级配置**，对这台电脑上的所有 Maven 项目生效。

</details>

**6. `docker` 命令报「连接不上 daemon」，最可能的原因是什么？**

<details>
<summary>参考答案</summary>

- Docker 是**客户端 / 服务端架构**：`docker` 命令是客户端，真正管理镜像和容器的是后台的守护进程（daemon），两者通过一个 socket 文件通信。
- 报错 `failed to connect to the docker API ... Is the docker daemon running?` 说明客户端在，但**守护进程没有运行**。在 Mac 上最常见的原因就是 **Docker Desktop 没有启动**。
- 解决：打开 Docker Desktop（或运行 `open -a Docker`），等菜单栏鲸鱼图标稳定后，再运行 `docker version`，看到 Server 部分就说明连上了。
- 其他可能：Docker Desktop 还在启动中；当前 `docker context` 指向了别的环境。

</details>

### 进阶题（和这次踩的坑有关）

**7. 为什么把 JDK 解压到 `~/Library/Java/JavaVirtualMachines` 就能被系统识别，解压到 `~/tools` 却不行？**

<details>
<summary>参考答案</summary>

- macOS 的 `/usr/libexec/java_home` 和 `/usr/bin/java` 替身，只会在两个约定位置查找 JDK：系统级 `/Library/Java/JavaVirtualMachines` 和用户级 `~/Library/Java/JavaVirtualMachines`。
- 目录下的 JDK 要保持 macOS 的包结构（`xxx.jdk/Contents/Home`、`Contents/Info.plist`），系统会读取 `Info.plist` 获取版本信息。
- 放在 `~/tools` 也能用，但系统找不到它，就必须把 `JAVA_HOME` 写成固定路径，并把 `$JAVA_HOME/bin` 手动加进 `PATH`。

</details>

**8. 终端配了 HTTP 代理，为什么 `curl` 下载变慢了，Maven 却没受影响？**

<details>
<summary>参考答案</summary>

- `curl` 等很多命令行工具会自动读取 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量，所以访问国内镜像也先绕到远程代理服务器，速度大幅下降。`--noproxy '*'` 表示这次请求不走代理。
- Java 程序（包括 Maven）**默认不读取这两个环境变量**。Java 的代理要通过 JVM 参数 `-Dhttps.proxyHost` 设置，Maven 的代理要在 `settings.xml` 的 `<proxies>` 里配置。所以 Maven 是直连阿里云的。
- 同一个环境变量，不同程序的处理方式可能不同。排查网络问题时，要先确认**这个程序到底有没有走代理**。

</details>

**9. IDEA 的「项目 SDK」和「导入程序的 JDK」有什么区别？哪个必须设成 17？**

<details>
<summary>参考答案</summary>

- **项目 SDK**：编译和运行你的代码时使用的 JDK，决定代码能用哪个版本的语法和类库。**必须设成 17**，和终端里的 `JAVA_HOME` 保持一致。
- **导入程序的 JDK**：IDEA 在后台运行 Maven、解析 `pom.xml` 生成项目结构时使用的 Java，只影响「读取项目配置」这一步，用 IDEA 自带的运行时也可以。
- 这两个设置分开，是因为「用来运行工具的 Java」和「项目本身要求的 Java」可以不同。

</details>
